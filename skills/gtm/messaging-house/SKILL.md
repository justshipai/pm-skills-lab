# Messaging house

Scattered messaging — every deck, page, and rep saying something different — is what makes a product forgettable. A "messaging house" is the shared architecture that fixes it: **one core message** (the roof), a few **benefit pillars** (the walls) that support it, **proof** under each (the foundation), and per-audience translations. This skill builds that, leading with customer benefits, not features.

## The structure

- **Roof — the core message.** One sentence: the single most important thing to land about the product, in the customer's terms (the value, not the category). Everything else supports this.
- **Pillars — 2-4 supporting messages.** The few benefit themes that prove the core message. **Benefit-led** ("ship faster"), each a *because* of the core promise — not feature names.
- **Foundation — proof per pillar.** For each pillar, the evidence: capabilities, data/metrics, customers, specifics that make the benefit believable. (This is where features finally appear — as proof, not as the message.)
- **Per-audience translation.** The same house, re-voiced for each audience (e.g. exec vs. practitioner vs. developer) — what each cares about, in their language. The architecture is constant; the emphasis shifts.

## The judgment this skill encodes

- **Benefits up top, features as proof.** Lead with what the customer gets; relegate features to the foundation as evidence. A pillar named "AI-powered" is a feature; "you never start from a blank page" is a benefit.
- **One core message, ruthlessly.** If you have three "main" messages, you have none. Force a single roof.
- **Pillars must support the roof and be distinct.** 2-4, mutually reinforcing, non-overlapping; each clearly *why the core promise is true*.
- **Proof or it's a claim.** Every pillar needs evidence; an unproven benefit is marketing air. If proof is thin, that's a finding (build the proof or soften the claim).
- **Tie to positioning, not taste.** The core message should follow from the product's differentiated value (pairs with `positioning-statement`), not a clever line. Slogans are downstream, not the message.
- **Make it usable.** The output is a reference sales/marketing/product can pull consistent copy from — not a single tagline.

## Process

1. **Core message (roof)** — the one thing, customer-benefit framed, from the positioning.
2. **Pillars (2-4)** — the benefit themes that support it; distinct and reinforcing.
3. **Proof per pillar** — the evidence (capabilities, data, customers) that makes each believable.
4. **Per-audience translation** — re-voice the house for the key audiences.
5. **Gap check** — pillars with weak proof; overlap; whether it all rolls up to the roof.

## Output format

```
# <Product> — Messaging House

## Core message (roof)         (one sentence; customer benefit)
## Pillars (the walls)
   - Pillar 1 (benefit) → proof: …
   - Pillar 2 (benefit) → proof: …
   - Pillar 3 (benefit) → proof: …
## Per-audience translation     (e.g. exec / practitioner / buyer — emphasis & language)
## Gaps                         (weak proof; overlaps; does it roll up?)
```

## Anti-patterns to refuse

- A tagline/slogan instead of a message architecture → Build the full house.
- Feature names as pillars → Reframe each as a customer benefit; features become proof.
- Three "core" messages → Force one roof.
- Pillars with no proof → Add evidence or flag the gap.
- One-size message for all audiences → Translate the house per audience.
